5. Known Constraints and Invariants

5.1 Must not break

· AevumDB single-writer FileLock: one process per database directory.
  The scheduler runs in-process, not as a separate binary.
· Backward compatibility: /growth/* and /api/growth/* must
  continue to work until explicitly migrated (see
  intelligence-integration-v1.md Section 5.7).
· Deploy whitelist: additions to frontend/ must be in whitelisted
  paths (*.html, sitemap.xml, robots.txt, learn/, css/,
  js/, img/, components/). docs/, content/, assets/,
  api/ are not deployed by aevum-deploy.
· Architecture canon: three documents define the model. Code must
  conform, not override.

5.2 Can break safely (with tests)

· Any backend internal module structure.
· Route registration approach (as long as URLs stay stable).
· Logging format (as long as it remains structured).

5.3 Cannot break

· Canonical URLs already live: /growth, /api/growth/*.
· Static site content served by aevum-deploy.
· Apache SSL and existing ProxyPass for /growth and /api/growth.
